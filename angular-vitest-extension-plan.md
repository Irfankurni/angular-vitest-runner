# Implementation Plan: Angular + Vitest VS Code Extension

## Overview
This document outlines the architecture and implementation steps for building a VS Code extension that integrates Angular's Vitest testing environment directly into the VS Code Test Explorer. 

Crucially, this extension leverages the **Angular CLI (`ng test`)** rather than calling Vitest directly. This ensures that all Angular-specific build pipelines, environment variables, and dependency injections remain intact as defined in `angular.json`.

---

## Phase 1: Workspace Initialization & Context Mapping ✅
**Goal:** Ensure the extension activates in the correct environment and accurately maps test files to their respective Angular projects.

- [x] **Extension Scaffolding:** Set up the basic VS Code extension boilerplate (TypeScript, `package.json`, `extension.ts`).
- [x] **Activation Events:** Configure `package.json` to activate on `onLanguage:typescript` or `workspaceContains:angular.json`.
- [x] **Parse `angular.json`:**
  - Read and parse the workspace's `angular.json`.
  - Extract all projects and their respective `root` or `sourceRoot` directories.
  - Verify that the target project utilizes a Vitest builder in `architect.test.builder` (e.g., `@angular/build:unit-test`, `@analogjs/platform:vitest` or a custom executor).
- [x] **Path Resolution:** Create a utility function that takes a `.spec.ts` file path and returns the associated Angular project name based on the `angular.json` mapping.

## Phase 2: VS Code Testing API Integration ✅
**Goal:** Connect the extension to the native VS Code Test Explorer UI.

- [x] **Initialize Test Controller:** Instantiate `vscode.tests.createTestController('angularVitestController', 'Angular Vitest').
- [x] **Setup Run Profiles:** Add `Run` and `Debug` profiles using `controller.createRunProfile()`.
- [x] **Test Item Hierarchy:** Define internal models to represent Workspace -> Project -> Test File (`.spec.ts`) -> Suite (`describe`) -> Case (`it`).

## Phase 3: Test Discovery & AST Parsing ✅
**Goal:** Statically analyze test files to populate the Test Explorer and enable inline Code Lens (Run/Debug buttons) without executing the tests.

- [x] **Implement AST Parser:** Use the `typescript` compiler API to read `.spec.ts` files.
- [x] **Extract Test Nodes:** Identify `describe` and `it` (or `test`) function calls.
- [x] **Map Line Numbers:** Extract the exact line numbers and test names to map them to `vscode.TestItem`.
- [x] **File Watcher Integration:** Implement `vscode.workspace.createFileSystemWatcher` to dynamically add/remove test items in the Test Explorer as the developer writes or deletes tests.

## Phase 4: Execution via Angular CLI (Child Process) ✅
**Goal:** Run the tests using the local Angular CLI and pass necessary arguments to filter specific tests.

- [x] **Locate Local CLI:** Resolve the path to `./node_modules/.bin/ng` to ensure version consistency.
- [x] **Construct Execution Command:**
  - Base command: `ng test <project-name>`
  - File filter: `--include <relative-path-to-file>`
  - Test name filter (for specific `it` blocks): Pass args to the underlying builder, e.g., `-- --testNamePattern="<test-name>"`
  - Output formatting: `-- --reporter=json` (Ensure Vitest outputs JSON for programmatic parsing).
- [x] **Process Spawning:** Use Node's `child_process.spawn` to execute the command within the workspace directory.

## Phase 5: Output Sanitization & UI Updating ✅
**Goal:** Parse the CLI output, separate Angular build logs from Vitest JSON output, and update the VS Code UI.

- [x] **Output Sanitization (Crucial Step):** 
  - Capture `stdout` from the child process.
  - Write a regex or string extraction utility to ignore Angular's build logs (e.g., "Building...", "Generating...") and isolate the valid JSON block generated by Vitest's JSON reporter.
- [x] **Parse JSON Results:** Deserialize the isolated JSON output.
- [x] **Map Results to Test Items:** Iterate through the JSON results and match them with the corresponding `vscode.TestItem` IDs.
- [x] **Update TestRun State:** Use `TestRun.passed()`, `TestRun.failed()`, or `TestRun.skipped()` to update the UI icons.
- [x] **Error Handling & Stack Traces:** For failed tests, extract the failure message and stack trace from the JSON, and attach them using `vscode.TestMessage`. Handle non-zero exit codes caused by Angular build failures (displaying "Build Failed" appropriately).

## Phase 6: Polish & Advanced Features
**Goal:** Enhance the developer experience.

- [ ] **Debug Mode:** Integrate with VS Code's `vscode.debug.startDebugging` by attaching a Node debugger to the Angular CLI process.
- [ ] **Watch Mode Support:** Implement a toggle for continuous testing (passing `--watch` to the CLI) and maintaining a persistent child process.
- [ ] **Configuration Settings:** Expose settings in `package.json` (`contributes.configuration`) allowing users to define custom CLI paths, default arguments, or custom builders.
